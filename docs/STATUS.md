# 현재 목표와 M1 상태

최종 갱신: 2026-09-20 (KST)

M1의 장기 목표는 MEM의 운영 구조를 에이전트로 재현하는 것이다. 현재 선행 작업은
**ALFRED 원본 규칙 기반, 단일 씬의 Subtask 오라클 유도 프로토타입**이다.
메모리 구현이나 MEM의 learned VLA/video encoder/language-memory 기구 재현은
아직 시작하지 않았다. 기존 THOR 5.0 `run_agent_loop`는 별도 기준선으로 남아 있다.

## 확보된 것

- 공식 ALFRED 커밋 `f91f4c0c96c7a29f33d0557f86b0a21035379b3b`,
  AI2-THOR 2.1.0, Python 3.7 격리 환경, 공식 `json_2.1.0`을 설치했다.
  설치 명세와 해시는 [alfred/README.md](../alfred/README.md)에 있다.
- FloorPlan15/train의 지정된 세 trial을 원본 초기화와 공식 `va_interact`로
  재생해 모두 공식 목표를 달성했다: 와인병 26/26, 머그잔 28/28,
  사과 조각 가열 109/109 행동 성공. 이는 전문가 기준 재생이며 VLM 성과가 아니다.
- 공식 평가기 연결 대조: 마지막 배치 생략 3건, 칼 없이 절단 1건,
  잘못된 receptacle 1건, 조기 완료 1건이 모두 공식 목표 실패였다.
  수도 조작의 내부 `Pass`/`CleanObject`와 세척 이력, 전자레인지 가열 이력,
  절단으로 생성된 세 조각과 후속 pickup 대상도 원시 로그에서 확인했다.
- ALFRED 전용 RGB/언어 VLM 어댑터, 정수 bbox→mask 변환, 공식 성공 판정,
  행동/실패 예산, 이벤트·RGB·mask·HTTP 요청 보존, manifest와 결과 요약을 추가했다.
  현재/과거 RGB의 역할과 현재 화면 bbox grounding을 프롬프트에 명시하고
  action 전후 RGB 변화율도 기록한다. 기존 회귀 검사 포함 단위 테스트 29개와
  Ruff 검사가 통과했다. 이 변경은 아직 VLM episode로 검증하지 않았다.

## 미완료와 한계

- 과제별 VLM 탐색 3회를 실행했으나 공식 성공은 0회다. 와인병은 탐색 중단,
  형식 오류, 60행동 예산 소진; 머그잔은 40행동 예산 소진, 10회 실행 실패,
  회전 반복; 사과는 40·60행동 예산 소진과 회전 반복으로 끝났다.
  조작 대상으로 bbox를 선택한 성공 궤적이 없다. 고정 계획의 3회 재검증은
  시작하지 않았고 **등록된 VLM 오라클은 없다**.
- 와인병의 세 탐색에는 과거 RGB 5장까지 전달되는 초기 버그가 있었다.
  요청 감사에서 현재 5장 총량 제한을 초과한 것으로 표시했다. 현 코드에서는
  현재 RGB와 같은 subtask의 과거 RGB 최대 4장만 보낸다. 와인병 탐색을
  계약 준수 성과로 사용하지 않는다.
- 초기 원시 상태 해시는 Unity 물리 미세 변동으로 실행마다 다르다. 객체 ID,
  배치 관계, 토글·청결, 시작 자세와 상태 이력만 정규화한 초기 의미 해시는
  같은 과제의 재실행에서 일치했다. VLM 실행 일반화나 benchmark 근거는 없다.
- 실험 중 코드가 미커밋으로 수정되어 과거 episode의 정확한 runner 파일 해시는
  **unknown**이다. 향후 실행은 runner/manifest 해시를 요약에 기록한다.
  원본 `runs/alfred/`는 Git에서 무시되는 local-only artifact이며,
  [결과 요약](../alfred/results.json)은 추적된다.

## 다음 작업

새 프롬프트와 RGB 변화 계측을 적용할 탐색 예산·중단 기준·후보 판정 기준을
사용자와 먼저 정한다. 그 전에는 VLM episode를 실행하지 않는다. 후보가 공식
성공에 도달하면 계획과 프롬프트를 고정한 채 원본 초기 상태부터 과제당 3회
재검증한다.

원시 요청·응답과 행동 이벤트의 재분석에서 9개 탐색은 정책 행동 271회 중
회전/시선 230회, 전진 41회, bbox 조작 0회였다. 전진 실패 13회는 와인병의
`Cube.527` 3회와 머그잔의 `Pan_7e5e2cad` 10회에 대한 재시도였다. 따라서
현 실패 근거는 bbox 품질보다 탐색 종료·접근·대상 grounding 이전 단계다.
머그잔·사과 요청은 이미지 1–5장(모두 300×300 PNG)과 prompt만 담겼다.

사용자 승인 뒤 새 진단 1회씩을 추가했으나 세 과제 모두 `policy_loop`으로
공식 실패했다(와인병 4행동/실패 3, 머그잔 5/3, 사과 4/0). 모든 새 요청은
이미지 1–5장 및 prompt만 포함했고 감사에 통과했다. 과제별 탐색 자료는 이제
각 4회이나 성공 후보·검증 episode는 여전히 0회다.
