# nexus-memory

“주방을 청소해 줘”, “저녁 식사를 준비해 줘” 같은 고수준 요청을 에이전트가 스스로 계획하고 수행할 때, 장기 기억 설계가 완료율과 효율에 어떤 차이를 만드는지 검증하는 연구용 저장소.

**첫 PoC: AI2-THOR에 고수준 토이 태스크 5종을 구성하고, A(MEM-inspired 장기 기억 갱신)와 B(NexusSum에서 착안한 계층적 메모리 압축)를 동일한 에이전트에서 비교합니다.**

현재는 설계 단계입니다. 시뮬레이터, 에이전트, 메모리 모듈과 평가 환경은 아직 구현하지 않았으며 실험 결과도 없습니다.

## 연구 질문과 배경

큰 목표를 수행하는 에이전트는 어디를 탐색했는지, 어떤 물건을 처리했는지, 무엇에 실패했는지 기억해야 합니다. 이 정보가 사라지거나 오래된 상태로 남으면 작업을 누락하거나 반복할 수 있습니다.

[MEM](https://arxiv.org/html/2603.03596v2#S3)은 고수준 정책이 관찰·기존 언어 기억·목표를 바탕으로 다음 하위 작업과 갱신된 언어 기억을 생성하는 구조를 제안합니다. 장기 기억에는 정보 제거와 압축도 포함되며, 저수준 정책에는 단기 시각 기억을 사용합니다.

[NexusSum](https://arxiv.org/html/2505.24575v1)의 계층적 요약 원리를 장기 기억 관리에 적용해 다음 질문을 검증합니다.

> 동일한 모델과 기억 예산에서, 계층적 장기 기억은 MEM-inspired 누적 갱신보다 고수준 목표의 자율 수행 성공률을 높이거나 전체 수행 비용을 줄이는가?

서사 요약의 성과가 행동 기억으로 이어진다는 보장은 없습니다. 계층적 압축이 필요한 물체·위치 정보를 잃거나, 상태 갱신을 어렵게 만들거나, 추가 호출 비용만 늘릴 가능성도 평가합니다.

## 주 실험: 고수준 토이 태스크 5종

아래는 구현할 후보입니다. 선택한 AI2-THOR 버전과 장면의 물체·행동 지원을 확인한 뒤 메뉴, 세척·보관 규칙과 완료 조건을 확정합니다. 실제 요리·청소 전체를 재현하는 환경을 뜻하지 않습니다.

| 고수준 요청 | 자율적으로 결정할 내용 | 기억 관련 평가 포인트 |
| --- | --- | --- |
| 주방을 청소하고 정리해 줘 | 대상 탐색, 세척·수납 순서 | 처리 누락, 이미 처리한 물건 재처리 |
| 두 사람의 저녁 식사를 준비해 줘 | 정해진 메뉴의 재료 준비와 상차림 순서 | 준비 단계와 수량 혼동 |
| 장을 봐 온 물건을 정리해 줘 | 물건 확인, 종류별 보관 | 탐색한 보관 위치와 진행 상황 |
| 식사 후 뒷정리를 해 줘 | 식기 수거, 세척, 수납 | 세척 전후 상태와 미완료 작업 추적 |
| 아침 식사 준비 중 추가된 손님에 맞춰 준비해 줘 | 진행 중인 계획 수정 | 완료 상태 보존, 추가 요구 반영 |

에이전트에는 목표, 메뉴·인원 등의 요구 사항과 적용할 규칙을 제공하고, 하위 작업 목록이나 정답 행동 순서는 제공하지 않습니다. 목표 분해, 탐색, 행동 순서, 실패 후 재계획, 종료 판단은 에이전트가 수행합니다. 평가 조건은 지시와 일치해야 하며, 알려주지 않은 요구 사항으로 실패 판정을 내리지 않습니다.

한 에피소드 안에서는 장면 상태와 기억을 유지합니다. 현재 관찰만으로 모든 진행 상황을 알 수 없도록 구성하고, 탐색 위치·완료 작업·목표 변경이 이후 의사결정에 영향을 주게 설계합니다. 목표 변경은 사전에 정한 진행 이벤트에서 A/B 양쪽에 같은 내용으로 전달하며, 그 이벤트에 도달하지 못한 실행도 결과에 포함합니다.

태스크마다 물체 배치·수량·초기 상태를 바꾼 여러 에피소드를 실행합니다. 다섯 번의 데모가 아니라 다섯 태스크 유형에 대한 반복 비교가 목표입니다.

## A/B 시스템 설계

공통 실행 흐름은 목표·관찰·기억을 바탕으로 기억을 갱신하고 다음 하위 작업을 선택한 뒤, 행동을 실행하고 결과를 관찰하는 루프입니다.

| 구성 | A: MEM-inspired | B: 계층적 메모리 압축 |
| --- | --- | --- |
| 고수준 목표·관찰·단기 기억 | 공통 입력 규칙과 최근 관찰 버퍼 | 동일 |
| 장기 기억 | 이전 언어 기억을 현재 관찰·실행 결과에 따라 갱신·압축 | 작업별 요약을 유지하고 상위 요약으로 통합·압축 |
| 하위 작업 선택 | 갱신된 기억을 사용하는 공통 계획 인터페이스 | 동일 |
| 이동·조작 | 공통 행동 도구와 실행기 | 동일 |
| 비교 예산 | 동일한 기억 토큰 상한·최대 행동 수 | 동일, 추가 요약 비용도 측정 |

### A: MEM에서 가져오는 것과 달라지는 것

A는 관련 정보를 유지하고 불필요한 정보를 제거·압축하며 다음 하위 작업을 선택하도록 구현합니다. 기록을 무한히 덧붙이거나 무조건 잘라내는 방식으로 약화하지 않습니다.

원 논문의 학습된 고수준 정책, 비디오 인코더, 연속 로봇 제어를 동일하게 재현하는 것은 초기 범위 밖입니다. 공통 LLM/VLM과 AI2-THOR 행동 실행기로 그 역할을 대체하고, 단기 기억도 양쪽에 동일하게 제공합니다. 논문과 구현의 대응 및 차이를 기록하며 **MEM-inspired 시뮬레이션 베이스라인**으로 명명합니다. 결과는 원래 MEM 전체 시스템의 재현이나 우열 비교로 해석하지 않습니다.

### B: 추가로 검증할 설계

최근 관찰·행동·결과, 작업별 기억, 전체 목표 수준 기억을 구성합니다. 보존할 정보는 물체의 마지막 관찰 위치·상태, 완료·미완료 목표, 실패 이력, 목표 변경입니다. 계층 수, 통합 조건, 갱신 주기, 상태 충돌 처리 방식은 개발용 에피소드에서 정한 뒤 평가 전에 고정합니다.

계층화의 효과를 보기 위해 A/B에 같은 모델과 보존 정보 지침을 사용합니다. 요약 호출 횟수 등 불가피하게 달라지는 부분은 명시하고 전체 비용에 포함합니다.

## 환경과 정보 접근 범위

[AI2-THOR](https://github.com/allenai/ai2thor)를 실행 환경으로 사용하고, 고수준 태스크와 평가기를 직접 구성합니다. [ALFRED](https://github.com/askforalfred/alfred)는 작업 구성·행동 인터페이스·기본 평가를 참고하는 보조 자료입니다. 표준 ALFRED 평가의 태스크별 초기화 루프를 그대로 사용하지 않습니다. ALFRED 구성 요소를 재사용하면 호환 버전을 고정하고, 커스텀 결과와 표준 점수를 분리합니다.

시뮬레이터 전체 상태는 성공 판정용으로 분리합니다. 에이전트 입력은 관찰 가능한 정보로 제한하며, RGB와 가시 물체 메타데이터 중 무엇을 사용하는지 명시합니다. 전체 상태를 제공하는 진단 실행은 oracle 조건으로 따로 기록합니다.

위치 지도, 체크리스트, 계획 기록, 도구 내부 캐시도 기억입니다. 지속되는 정보는 모두 목록화해 A/B에서 동일하게 통제하고, 에이전트가 읽을 수 있는 과거 정보는 기억 예산에 포함합니다. 계층별 저장량과 매 호출에 실제 전달하는 토큰 수를 모두 기록하며, 분석용 원본 로그를 통한 우회 접근은 허용하지 않습니다.

## 평가 계획

주요 지표는 **고수준 목표 전체 성공률**과 **목표 조건 달성률**입니다. 일부 작업만 끝내고 종료한 실행과 제한 시간·행동 수에 도달한 실행도 포함합니다.

- 행동 효율: 전체 행동 수, 중복 처리, 재탐색, 작업 누락, 잘못된 물체·상태 선택.
- 실행 비용: 계획·기억 갱신을 포함한 총 토큰·호출 비용, 벽시계 실행시간, 의사결정 지연.
- 실패 원인: 인식, 이동·조작, 계획, 기억 누락, 오래된 기억, 목표 변경 미반영을 로그로 분석.

A/B는 같은 초기 상태와 목표 변경 규칙에서 시작하지만, 선택한 행동과 이후 관찰은 달라질 수 있습니다. 동일한 궤적을 강제하지 않고 각각 끝까지 실행합니다. 여러 seed와 초기 상태에 대한 짝지은 비교를 수행하고, 태스크별 결과·유형별 평균의 전체 평균·실행 수·변동성을 보고합니다.

개발용 배치와 평가용 배치를 분리합니다. 모델·프롬프트·예산·종료 규칙·최소 의미 있는 성능 차이·허용 비용 증가를 평가 전에 고정합니다. 단일 조건을 과도하게 압축해 차이를 만들지 않도록 여러 기억 예산에서 성능과 비용 변화를 확인합니다.

## 보조 실험과 결과 해석

“아까 보관한 컵을 가져오기”와 위치 변경 기억 테스트는 메모리 모듈 디버깅 및 실패 분석에 사용합니다. 현재 관찰만 사용하거나 최근 이력만 사용하는 조건도 보조 비교로 추가할 수 있습니다. 이 결과만으로 고수준 목표 수행 개선을 주장하지 않습니다.

| 관찰 결과 | 해석 |
| --- | --- |
| B가 여러 태스크·초기 상태에서 A보다 전체 성공률을 높임 | 해당 시뮬레이션 조건에서 계층적 기억의 가치를 지지 |
| 성공률은 비슷하고 총 행동·비용이 줄어듦 | 효율 개선 가능성. 추가 요약 비용을 포함해 판단 |
| 쉬운 보조 기준선보다 좋지만 A와 차이가 없음 | MEM-inspired 갱신 대비 추가 가치는 아직 확인되지 않음 |
| 일부 태스크에서만 개선되거나 중요한 사실을 잃음 | 적용 조건과 실패 원인을 분석하고 보존·갱신 규칙 재검토 |
| 인식·조작 실패가 대부분이거나 모든 조건이 쉽게 성공함 | 기억 설계의 차이를 평가할 수 있는지 환경과 실행기 재점검 |

이 PoC의 목표는 고수준 작업을 수행하는 데 계층적 기억이 실질적인 이점을 주는지 판단하는 것입니다. 긍정적인 결과도 선정한 토이 환경과 구현 범위에 한정해 해석합니다.

## 장기 수행과 15분의 의미

처음부터 여러 하위 작업이 이어지는 고수준 목표를 주 실험으로 삼습니다. 장기적으로 15분 이상 연속 수행도 탐색하되, 주요 성공 기준은 목표 달성과 비용입니다. 벽시계 시간, 행동 수, 과거 정보를 다시 사용하기까지의 간격을 함께 기록합니다. 인위적인 대기나 느린 추론으로 실행시간을 늘리지 않으며, 이산 시뮬레이션 시간을 실제 로봇의 연속 제어 시간과 동일시하지 않습니다.
